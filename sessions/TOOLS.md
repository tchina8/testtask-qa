# Журнал инструментов

> Только дополняется, старые записи не редактируются. Сюда попадает всё, что вы
> добавили в проект или окружение ради этой задачи: библиотеки, CLI-утилиты,
> линтеры, MCP-серверы, плагины и скиллы агента, хуки, внешние сервисы, контейнеры.
>
> Разовый вызов уже установленного инструмента сюда не пишется — он идёт
> в таблицу инструментов внутри файла сессии.
>
> Тупиковая попытка — тоже запись: поставили, не подошло, сняли. Это как раз интересно.

## Шаблон записи

```markdown
## YYYY-MM-DD · Сессия N · <инструмент> vX.Y

- **Тип:** библиотека / CLI / MCP / плагин / скилл / хук / сервис
- **Установка:** `<точная команда>`
- **Зачем:** какую задачу решает
- **Область:** проект или глобально
- **Проверка:** чем убедились, что работает
```

Удалённый или заменённый инструмент фиксируется так же — с пометкой
**удалён** / **заменён на X** и причиной.

## 2026-08-16 · Сессия 1 · Node.js LTS v24.19.0 (npm 11.17.0)

- **Тип:** среда выполнения (CLI)
- **Установка:** `winget install --id OpenJS.NodeJS.LTS -e --accept-source-agreements --accept-package-agreements --silent`
- **Зачем:** закрывает сразу две задачи — стенд для приложения (`http-server`
  через `npx`) и автотест на `@playwright/test`. Альтернативой был Python,
  отклонён: Playwright на Python — порт основной реализации, примеров и трейсов
  меньше, а выигрыш только в том, что команда стенда совпала бы с текстом задания.
- **Область:** глобально (машина)
- **Проверка:** `node --version` → `v24.19.0`, `npm --version` → `11.17.0`,
  `npx --version` → `11.17.0`.

> **Важно для следующих сессий.** После установки `node` **не появляется в PATH
> уже запущенных оболочек**. Проверено: в этой сессии `node --version` падает
> с `CommandNotFoundException`, хотя Node установлен. Перед командами Node нужна
> строка обновления PATH — она вынесена в `AGENTS.md`, раздел «Как запускать
> и проверять». Не делать из этой ошибки вывод, что Node отсутствует,
> и не ставить его повторно.

## 2026-08-16 · Сессия 1 · http-server v14.1.1

- **Тип:** CLI (запускается через `npx`, в зависимости проекта не добавляется)
- **Установка:** отдельной установки нет — `npx --yes http-server ./app -p 8765 -c-1`
- **Зачем:** стенд для тестирования. Локальный файл через `file://` не открыть:
  Playwright и встроенный браузер блокируют этот протокол.
- **Область:** проект
- **Проверка:** сервер поднят, `Invoke-WebRequest http://localhost:8765/` →
  **HTTP 200**. В логе сервера: `Starting up http-server, serving ./app`,
  `Cache: -1 seconds`, запись о запросе `GET /`. Сервер остановлен после проверки.

## 2026-08-16 · Сессия 1 · Python — **не установлен, попытка отклонена**

- **Тип:** CLI
- **Установка:** не выполнялась
- **Зачем:** задание предлагает стенд `python3 -m http.server 8765`
- **Что выяснилось:** `python3` в системе отсутствует; `python` в PATH есть,
  но это заглушка Microsoft Store (`WindowsApps\python.exe`) — `--version`
  печатает пустое `Python`, настоящего интерпретатора нет. Launcher `py` тоже
  отсутствует, установок в `Program Files` и `LOCALAPPDATA\Programs` нет.
- **Решение:** не ставить. Одна установка Node закрывает и стенд, и автотест;
  ставить два рантайма ради одной команды из текста задания смысла нет.
- **Проверка:** `where.exe python` → только путь в `WindowsApps`;
  `py --version` → команда не найдена.
