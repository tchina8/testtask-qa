# Журнал инструментов

> Только дополняется, старые записи не редактируются. Сюда попадает всё, что вы
> добавили в проект или окружение ради этой задачи: библиотеки, CLI-утилиты,
> линтеры, MCP-серверы, плагины и скиллы агента, хуки, внешние сервисы, контейнеры.
>
> Разовый вызов уже установленного инструмента сюда не пишется — он идёт
> в таблицу инструментов внутри файла сессии.
>
> Тупиковая попытка — тоже запись: поставили, не подошло, сняли. Это как раз интересно.

## Шаблон записи

```markdown
## YYYY-MM-DD · Сессия N · <инструмент> vX.Y

- **Тип:** библиотека / CLI / MCP / плагин / скилл / хук / сервис
- **Установка:** `<точная команда>`
- **Зачем:** какую задачу решает
- **Область:** проект или глобально
- **Проверка:** чем убедились, что работает
```

Удалённый или заменённый инструмент фиксируется так же — с пометкой
**удалён** / **заменён на X** и причиной.

## 2026-08-16 · Сессия 1 · Node.js LTS v24.19.0 (npm 11.17.0)

- **Тип:** среда выполнения (CLI)
- **Установка:** `winget install --id OpenJS.NodeJS.LTS -e --accept-source-agreements --accept-package-agreements --silent`
- **Зачем:** закрывает сразу две задачи — стенд для приложения (`http-server`
  через `npx`) и автотест на `@playwright/test`. Альтернативой был Python,
  отклонён: Playwright на Python — порт основной реализации, примеров и трейсов
  меньше, а выигрыш только в том, что команда стенда совпала бы с текстом задания.
- **Область:** глобально (машина)
- **Проверка:** `node --version` → `v24.19.0`, `npm --version` → `11.17.0`,
  `npx --version` → `11.17.0`.

> **Важно для следующих сессий.** После установки `node` **не появляется в PATH
> уже запущенных оболочек**. Проверено: в этой сессии `node --version` падает
> с `CommandNotFoundException`, хотя Node установлен. Перед командами Node нужна
> строка обновления PATH — она вынесена в `AGENTS.md`, раздел «Как запускать
> и проверять». Не делать из этой ошибки вывод, что Node отсутствует,
> и не ставить его повторно.

## 2026-08-16 · Сессия 2 · Встроенный браузер сессии — **скриншоты не работают**

- **Тип:** инструмент агента
- **Установка:** не требуется
- **Зачем:** исследовательское тестирование — клики, набор текста, разбор DOM
  и `getComputedStyle` через консоль. С этой частью справился полностью:
  все проверки TC-01…TC-11 выполнены им.
- **Что выяснилось:** действие `screenshot` падает с ошибкой
  `Screenshot timed out after 5s: the Browser pane is not displayed, so the page
  is not compositing frames` — панель браузера в этой сессии не отображается,
  и кадры не рендерятся. Ошибка воспроизводимая, обходного пути внутри
  инструмента нет.
- **Решение:** не отказываться от инструмента, а разделить роли — действия
  и разбор разметки остаются за встроенным браузером, скриншоты снимает
  Playwright отдельным скриптом `tests/capture-evidence.mjs`. Скрипт намеренно
  не `*.spec.js`: проверок в нём нет, и он не должен попадать в счёт автотестов.
- **Проверка:** ошибка получена дословно при первой же попытке снять пустое
  состояние; после переключения на Playwright снимки получены на обеих ширинах.

## 2026-08-17 · Сессия 3 · Встроенный браузер сессии + заглушка `localStorage`

- **Тип:** инструмент агента (разовый приём, не установка)
- **Установка:** не требуется
- **Зачем:** проверить находку А-01 (падение обработчика `submit` при `null`
  внутри массива записей) без стенда
- **Что выяснилось:** браузер отдаёт `app/index.html` как `data:`-URL с
  `origin: null`, настоящий `localStorage` там заблокирован — `Failed to read
  the 'localStorage' property from 'Window': Storage is disabled inside 'data:'
  URLs`. Это ровно то ограничение, о которое споткнулся наивный прогон.
  Обход: `Object.defineProperty(window, 'localStorage', { value: <заглушка> })`
  и прямой `form.dispatchEvent(new Event('submit', …))`.
- **Границы приёма:** годится только для находок в чистой логике, не зависящих
  от бэкенда хранилища. Вёрстку, реальную перезагрузку и поведение при отказе
  хранилища так проверять нельзя — и они не проверялись.
- **Проверка:** заглушка установлена (`installed: true`), при `[null]` в
  хранилище отправка валидной формы дала
  `Uncaught TypeError: Cannot read properties of null (reading 'email')`,
  контрольные пробы (невалидный email; запись без поля `email`) исключения
  не дали — значит падение узкое и приём различает случаи, а не ломает всё
  подряд.
