# BUG-01 — длинное значение без пробелов ломает вёрстку страницы

- **Статус:** **закрыт** 2026-08-17. Фикс применён к `app/index.html` вне сессии
  тестирования; у `li .name` и `li .meta` появился `overflow-wrap: anywhere`.
  Повторная проверка выполнена тем же чек-листом, отчёт —
  [../retest.md](../retest.md). Автотест `tests/bug-01-overflow.spec.js`,
  падавший на этом дефекте, стал зелёным: **2 passed**. Побочного ущерба
  не найдено — 16 из 16 позиций чек-листа в ожидаемом состоянии,
  необработанных исключений за прогон ноль.
- **Серьёзность:** средний
- **Где:** `http://localhost:8765/`, список «Зарегистрированные пользователи»,
  элементы `li > .name` и `li > .meta`
- **Ширина экрана:** 360 **и** 1280 (воспроизводится на обеих)
- **Найден:** тест-план, проверка TC-12

## Шаги воспроизведения

1. Поднять стенд: `npx --yes http-server ./app -p 8765 -c-1`, открыть
   `http://localhost:8765/`.
2. Очистить хранилище: в консоли `localStorage.clear()`, перезагрузить страницу.
3. В поле «Имя» вставить строку из 500 символов `Я` без пробелов
   (`'Я'.repeat(500)`).
4. В поле «Email» вставить `'a'.repeat(300) + '@mail.ru'` — 308 символов
   без пробелов.
5. Пароль и повтор — `Parol123`, отметить согласие.
6. Нажать «Отправить».

## Ожидаемый результат

Запись видна внутри карточки списка, страница не прокручивается вбок.

`SPEC.md` → «Состояния», строка **«Есть данные»**: «Форма и список записей» —
список должен быть виден пользователю. `SPEC.md` → «Окружение и доказательства»:
проверяемые ширины 360 и 1280; на обеих список обязан оставаться в пределах
карточки.

Ограничение длины полей в `SPEC.md` намеренно не задано («Намеренные
недосказанности», п. 3), поэтому **сам факт приёма длинной строки дефектом
не считается** — дефект в том, что принятая строка разрушает вёрстку.

## Фактический результат

Строка не переносится (у `.name` и `.meta` `overflow-wrap: normal`,
`word-break: normal`), выходит за карточку и растягивает всю страницу:

| Ширина окна | `documentElement.scrollWidth` | Во сколько раз шире окна |
|---|---|---|
| 1280 | 5327 | ×4,2 |
| 360 | 4943 | ×13,7 |

Карточка формы заканчивается на `x = 880` (при 1280), текст записи уходит
за правый край окна. Появляется горизонтальная прокрутка всей страницы;
чтобы прочитать email, пользователю нужно листать вбок примерно 4000 px.
Данные при этом сохраняются корректно — ломается только отображение.

## Доказательство

**1. Скриншот** — `reports/screenshots/bug-01-long-values-1280.png` (ширина 1280).
Список конкретных ответов по картинке:

- текст записи виден — да, но обрывается на правом краю окна и продолжается
  за его пределами;
- выходит ли значение за карточку — **да**, белая карточка кончается, строка
  из `Я` идёт по серому фону дальше вправо;
- наезжает ли кнопка на поле — нет, форма не пострадала;
- одинаковы ли элементы списка — **нет**: запись `Иван Петров` умещается
  в карточку, запись с длинным именем выходит за неё.

**2. Скриншот всей страницы** — `reports/screenshots/bug-01-long-values-360-fullpage.png`:
изображение 4943×1038 px при окне 360 px. Карточка занимает левые 7 % ширины,
остальное — уехавшая строка.

**3. Разбор разметки** (консоль браузера, ширина 1280):

```
{ "tag": "UL",   "cls": "list", "scrollWidth": 4902, "clientWidth": 430 }
{ "tag": "DIV",  "cls": "name", "scrollWidth": 4902, "clientWidth": 430 }
{ "tag": "DIV",  "cls": "meta", "scrollWidth": 2036, "clientWidth": 430 }
getComputedStyle('.meta') → { overflowWrap: "normal", wordBreak: "normal",
                              whiteSpace: "normal", overflow: "visible" }
```

**Почему одного скриншота не хватило бы.** По картинке видно, что текст уезжает
вправо, но не видно ни причины, ни масштаба: край окна обрезает строку, и на глаз
невозможно отличить «немного не поместилось» от «страница шире окна в четыре раза».
Числа `scrollWidth` и отсутствие `overflow-wrap` дают и то и другое — и сразу
указывают, где чинить. Обратное тоже верно: по одной разметке не видно, что
карточка визуально разрывается, поэтому оба доказательства приложены вместе.
